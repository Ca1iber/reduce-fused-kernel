# v012：K shared ring 的同步/异步对照

v011已经验证MCA异步拷贝可正确执行。保持tile512、128线程，先对FP8 H7168进行同几何比较。
控制组：v010；旧式single shared两次CTA同步；同步双缓冲；真实async两缓冲/三缓冲。
每轮消费前wait当前ticket，一次CTA同步兼顾当前数据可见性和上一轮slot复用安全。
消费前发起S-1距离的未来拷贝，保持K累加顺序。
预测async相对sync环形缓冲降低数据等待；更深prefetch增大in-flight量，但也增smem和ticket寄存器。
可证伪：生成代码没有copy-before-current-FMA；正确性不一致；同几何时延不降或native访存等待不改善。
初步结果不能否定hidden方向流水线、warp协作/shared元数据/输出重排；后续继续覆盖。



### 具体怎么试

每个线程块有 **128 个线程**，负责一个 token 的 **512 列输出**。它需要把这个 token 对应的 K 个 expert 的数据加起来。

比较了下面几种做法：

| 做法 | 怎么处理数据 |
|---|---|
| v010 基线 | 从显存读取一个 expert，直接计算，再处理下一个 |
| 单个 shared 缓冲区 | 读进 shared，线程同步，计算，再同步，然后覆盖缓冲区 |
| 同步双缓冲 | 用两个 shared 缓冲区轮换，但读取仍是同步的 |
| 异步双缓冲 | **提前读取下一个 expert，同时计算当前 expert** |
| 异步三缓冲 | 尝试提前读取更远的 expert，看看能否隐藏更多等待 |

### 那些术语是什么意思

- **ticket / wait**：异步读取发出去后，要检查它是否完成；完成了才能使用数据。
- **CTA 同步**：这个线程块里的线程互相等一下，保证数据可以安全读取、旧缓冲区可以安全覆盖。
- **S−1 距离**：两个缓冲区就提前读下一个；三个缓冲区就尝试提前读后面第二个。
- **保持 K 累加顺序**：可以提前读取，但仍按照原来的 expert 顺序相加，避免改变浮点计算结果。

### 最后测到了什么

FP8 h7168 上：

- 基线：**47.862 μs**
- 同步双缓冲：**50.770 μs**
- 异步双缓冲：**49.531 μs**

所以，**异步比同步双缓冲快了一些，但增加的 shared 搬运和同步成本仍让它慢于基线。** 只能说明这套实现没赢，不能据此否定所有流水线方案。
