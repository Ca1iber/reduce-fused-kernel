# v003：用 FP32/uint32 加速 FP8 输出（sc-16g）

## 改了什么

只修改 tileops/kernels/moe/reduce_fused.py 的 E4M3 输出分支：避开 SDK 的 FP32→FP64→通用 FP8 软件转换，用 FP32 和 uint32 位运算完成 RNE 编码。原归约顺序、128 线程、输入和 Op 接口保留。Base/XSF 使用原分支。

保留原 SDK 的 SATFINITE 语义：溢出/Inf 饱和、NaN 规范化、signed zero 与 nearest-even 舍入。使用 TileLang 原语，没有注入 C/C++，没有 FP16 中间近似。

## 验证

- 开发候选：202,752 次编码逐字节对照，0 差异；131 个现有正确性用例通过。
- 接入正式文件后：131 个现有正确性用例通过，16 个现有 benchmark 用例通过。
- 最终生成代码不再调用 __maca_cvt_float_to_fp8 / float2_to_fp8x2。Base H7168 的生成代码与改动前一致。
- 原始结果位于 raw/，实际接入源码、生成代码与补丁位于 codegen/。

我自己查了一下, 大概这个 SDK 的通用 FP8 转换路径走的是 __maca_cvt_float2_to_fp8x2 -> __maca_cvt_float_to_fp8 -> __maca_cvt_double_to_fp8 这么一条路下来
最终这个 __maca_cvt_double_to_fp8 走的是: 记住正负号 -> 处理特殊情况 -> 普通数 -> 把结果拼成一个字节
所以 SDK 的路径是: FP32 → FP64 → 读取64位编码 → 舍入、编码 → FP8
我们少走了转换成 double 的路径, 所以可以更快一点

## 附录2

1. 舍入: 就是挑一个最接近的, 能表示的值, 如果加号在两个整数中间, 就用"最近偶数"原则, 两边一样近就选偶数
2. 正常数: FP32 有 23 位小数, FP8 只能留 3 位, 所以需要处理掉 20 位, 但是不能直接扔掉, 后 20 位决定前面保留的部分要不要加 1
就和十进制保留两位小数一样: 1.23[4] -> 1.23, 1.23[8] -> 1.24

详解我们的代码, 先拆成三句:
    last_bit = (magnitude >> 20) & 1    last_bit 用来判断留下来的编码是奇数还是偶数, 处理"恰好在两个值中间"的情况
    rounded = (magnitude + 0x7ffff + last_bit) >> 20    右移 20 位, 扔掉低 20 位, 但是在这之前加了一笔数，让应该进位的情况能够产生进位, 至于 0x7ffff = 2^19 - 1 因为低 20 位一共能表示 2^20 种情况, 一半就是这个, 所以判断舍入的关键就是判断**被舍弃的部分有没有超过这一半**
    我们加了**半格 − 1 + last_bit**可以让超过一半的情况像保留部分进位
    - T.uint32(0x3c0): 舍入之后调整指数编码, FP32 的指数偏置是 127, E4M3 的是 7, 差 120... 120*8=960=0x3c0

3. 特别小的数: 先把真正的目标写出来
E4M3 非正规数能表示：

| 编码 | 数值 |
|---:|---:|
| 0 | 0 |
| 1 | `1/512` |
| 2 | `2/512` |
| 3 | `3/512` |
| …… | …… |

因此，转换这类数的目标其实很简单：

编码 = 对“输入绝对值 × 512”做最近偶数舍入
例如，输入是 `0.005`：

0.005 × 512 = 2.56
2.56 舍入成整数 → 3

编码 3 代表的 FP8 值：
3/512 = 0.005859375

**这就是我们希望得到的结果。每个小输入都按同样规则处理。**
### 那为什么代码写成加 `16384`？

因为 FP32 在 `16384` 附近，最后一位代表的数值恰好也是 `1/512`。

因此：

shifted = abs_value + 16384.0

这次加法保存成 FP32 时，会自动舍入成：

16384 + 某个整数/512

它替我们选好了上面那个整数。

接着：

denormal = bits(shifted) - 0x46800000

`0x46800000` 是 `16384.0` 的 FP32 编码。**两个整数编码相减，就能取出“增加了几个 1/512 单位”**&#65292;也就是所需的 FP8 编码。

输入的小数相当于多少个 1/512, 这个整数就是 FP8 非正规数的编码
假设输入 = 0.00390625 = 2/512 那我们希望得到的 FP8 编码就是 2

1. 加上 16384
shifted = 16384 + 2/512 = 16384.00390625
在这附近 FP32 的编码刚好有这样的关系:
| FP32 数值 | 它的二进制编码，用十六进制写 |
|---|---|
| `16384` | `0x46800000` |
| `16384 + 1/512` | `0x46800001` |
| `16384 + 2/512` | `0x46800002` |
| `16384 + 3/512` | `0x46800003` |
数值每增加 1/512, 编码刚好增加 1, 然后我们把这个浮点数的原始二进制编码当做整数读取, 有:
bits(16384.00390625) = 0x46800002
0x46800002 - 0x46800000 = 2 刚好就是我们需要的 FP8 编码 2, 表示 2/512

那当输入不是整数个单位时怎嘛办
0.005 × 512 = 2.56 个单位, 对应 FP8 需要选 3 个单位. 加上 16384 之后, FP32 也只能保存整数个这样的单位, 因此加法自动舍入为: 16384 + 3/512
读取他的编码, 再减去起点, 就能得到 3
