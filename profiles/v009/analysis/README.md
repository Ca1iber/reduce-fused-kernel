# v009：Base/XSF 的并行度参数实验（sc-16g）

## 范围

此前 v004 的 hidden 分块只应用于 FP8/Quantized，没有实测 Base/XSF；本轮补齐比较。
Base/XSF 原实现每 token 一个 CTA、128线程。候选保持 K 归约顺序、输出 dtype 和数值逻辑相同，仅改变线程数、hidden 划分。
FP8/Quantized 继续使用 v004。正式 kernel 文件未修改，本轮保存实验结果。

## 参数与方法

- tiny：原128线程，与整行64/256线程比较。
- 三个大 workload：原128线程，整行64/256线程，以及64线程/tile256和64/128/256线程×tile512/1024，共10配置。
- 共66个参数/workload组合，所有计时前输出与当前实现逐字节一致。
- 项目 bench_kernel：10 warmup，50 repeats×3 trials，L2 flush，cupti GPU timeline；各配置再测三轮并旋转/反转顺序，取三次结果中位数。
- seed=1235；tiny FP16，其他 BF16；h3072/h7168/tiny按项目阈值克隆输入，prefill使用相同地址。
- 每个 workload 都重新测原128线程基线；不混用上一容器的绝对延迟。
- 首轮跑到 XSF h7168 时被SIGKILL（exitcode -9），同时容器OOM计数由2增至3。已完成的46条数据保留；剩余两组改为独立进程后完成。复现脚本现按 workload 启动独立进程。

## 判断

- Base/XSF 的参数确实应实测。隐藏维度分块的收益不会自动从 FP8/Quantized 延伸到这两条路径。
- 原 v004 的1024列/128线程分块，在 h3072 上约快1%，在 h7168 上约慢8%，prefill也较慢。
- 三个大 workload 的所有七种分块配置，最快分块都没有超过整行256线程。
- 保留每 token 一个 CTA、改为256线程，在本轮八组中均最快。tiny/h3072延迟下降约1.8%～3.7%，prefill约1.6%～2.0%。h7168仅约0.5%～0.6%，不作为明显优化收益。
- 256线程仍维持原CTA数；hidden分块会增加CTA数，两者是不同的并行度调整。
- 分块增加路由/权重读取与CTA工作数量，可能解释部分变慢；本轮没有采集硬件计数器，无法确定寄存器、占用率、HBM事务或调度因素各占多少。

## 正确性

所有66组benchmark输入逐字节对照通过；对整行256线程，以及代表性的1024列/128线程分块，各运行完整现有测试：

- full_threads256_tile0：现有 131 个用例全部通过。
- split_threads128_tile1024：现有 131 个用例全部通过。
